## Policy to confirm with Records and the Mayor’s Office

Treat the receiving office named at registration as a required stop. A later office holding the document may forward it, including after signature. A copy receipt never transfers custody. Preserve the current wait for outstanding copies until staff decide whether copies are informational. Figure 5 leaves copy handling unspecified.

Distinguish Mayor reception, substantive approval, and signature. Ask staff which types can proceed on approval alone and who may act for the Mayor. Until classified, preserve the existing signature requirement on types that currently need signing. An intake verification or acknowledgement must never satisfy a required signature. Use the existing role and office assignments unless staff explicitly change delegation policy.

## Implementation order and acceptance

1. **Enforce the registered destination before completion (audit 1).** Trace manual, scanner, and pending-scan registration through the first transmission. Retain the original required destination separately if existing persisted fields cannot distinguish it reliably from later stops and copy recipients. In the completion transaction, check confirmed primary receipts for the current routing cycle, clearance, custody, and open transfers. A matching office name in the route plan is insufficient. Reuse the check for archive eligibility so a previously completed but inconsistent record cannot be newly archived unnoticed. Show the missing office and next action on the Documents screen. Test direct registration, Mayor as final destination, a later receiving office, copy-only receipt, cancellation, repeat visits, and completion racing with forwarding. A signed document for B must refuse completion at Mayor and permit it after B confirms receipt.

2. **Unify Mayor decisions and freeze the requirement (audits 2 and 4).** Store the effective requirement on each new registration, including scanner registration. Use it in review, signing, send, completion, lists and action controls. Apply type configuration edits prospectively. Route dedicated signing and generic status updates through the same validated transition, preserving supported clients and recording one decision. While signature is outstanding, either suppress acknowledgement or record it without disabling signing. Check role, current office, transit state, and receipt before recording the decision. Test both entry points, approval-only if adopted, a wrong-office actor, duplicate clicks, and a type edit while a record is open. Verify clearance, status, actor, timestamp and next permitted action together.

3. **Make signed forwarding consistent (audit 3).** Put the agreed authority and status check in the existing handoff service under its document lock. Pass the authenticated actor from both send routes. Preserve the special first handoff for registration or resubmission pending Mayor review. Align Documents and Transmissions controls and messages. Exercise the same role, office and status cases against both endpoints. After B receives a signed record, B can send to C, C must receive before acting, and the former holder and copy recipient cannot send as B. Include any explicitly authorized administrative exception in this matrix.

4. **Track returns and make resubmission truthful (audits 5 and 6).** Require a reason. For an interoffice physical return, create a return transmission to the actual origin and update custody on confirmed receipt. Reuse handoff locking and receipt history with an explicit return purpose so ordinary outbound rules still reject rejected documents. Handle rejection at the origin without a self-transfer. Reception records release to an external sender separately. On correction, retain the tracking number and revision history, reset the relevant clearance, and require fresh evidence for the revised cycle. Commit resubmission and its handoff together; use existing post-save handling for secondary logs and notifications. Test internal and external return, mistaken recipient, repeat confirmation, failed transaction, and successful commit followed by notification failure. Staff must see the saved revision and a single new handoff.

5. **Identify the final archive copy (audit 7).** Let the authorized archiver confirm one existing attachment, including when there is only one. Validate that the selected attachment belongs to this document and is readable at archive time. Record its stable reference with the archive in the existing transaction. Check which edits, replacements or deletion paths could invalidate that reference; preserve the archived version wherever required. Show the selected file on archive detail. Test an original scan plus a later signed scan, missing file, stale selection, concurrent replacement, duplicate archive, and restore. A previous archive with unknown final copy must remain identifiable as historical.
